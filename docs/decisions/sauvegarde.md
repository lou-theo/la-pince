# Copie quotidienne de la base

19/11/2026, mécanisme proposé par l'assistant et accepté ; point b changé à la demande du mainteneur le 19/11. Mise en place, restauration et ce qui a été constaté de l'une et de l'autre : `docs/auto-hebergement.md`, section Sauvegarde.

- (a) au-delà des 7 jours de Time Travel, une tâche planifiée GitHub Actions (`tools/sauvegarde/sauvegarde.yml`, modèle copié dans un repo privé à soi, jamais lancé depuis le repo public) exporte la base chaque jour et commite la copie seulement si l'export a changé, l'historique du repo donnant la base à toute date passée
- (b) copie compressée puis chiffrée par `age` vers une clé publique, la clé privée gardée dans le gestionnaire de mots de passe du mainteneur et jamais dans un fichier (dit par le mainteneur : « copie chiffrée, plus en clair ») ; une première copie en clair, retirée de l'historique du repo privé par force-push, reste lisible par le SHA de ses commits sur GitHub jusqu'à un nettoyage par son support, que rien ne déclenche seul (choisi par le mainteneur : « rien de sensible en l'état, c'est surtout pour faire propre », la copie ne portant que le groupe de démo)
- (c) jeton Cloudflare réservé à la sauvegarde, avec le seul droit D1 en écriture, pour que GitHub ne garde pas celui du déploiement, qui publie aussi le Worker
- (d) une copie se restaure dans une base neuve vers laquelle l'instance bascule, l'ancienne gardée ; elle doit redonner le compteur `sqlite_sequence`, dont dépend la détection d'une base restaurée (décision [Détection d'une base restaurée](base-restauree.md)), ce qui a été constaté le 19/11 (`docs/auto-hebergement.md`, Restaurer une copie).

Alternatives écartées : copie en clair (retenue d'abord, les jetons des liens n'y étant que hachés, décision [Partage du lien du groupe](partage-du-lien.md) ; écartée par le mainteneur) ; tâche sur la machine du mainteneur (ne tourne que machine allumée, pas reprenable par un autre groupe) ; tâche du Worker vers R2 (reste chez Cloudflare, donc ne protège pas de la perte du compte, et R2 demande une carte) ; fichiers attachés à une exécution dans le repo public (gardés 90 jours au plus, téléchargeables par tout compte GitHub).

Coût si faux : une copie qui échoue sans que personne lise le mail de GitHub laisse la base sans copie au-delà de 7 jours ; la clé privée perdue, aucune copie ne se restaure ; le repo grossit de la copie entière à chaque jour de changement, un fichier chiffré ne se stockant pas en différentiel.
